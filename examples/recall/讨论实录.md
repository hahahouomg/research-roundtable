# 一次真实的科研讨论

为文献检索实验做指标自检。交付单文件 Python 3 应用 main.py。固定相关论文集合 {A,C}，baseline 排名 [B,A,C]，candidate 排名 [C,B,D]。分别计算 Recall@3，运行 python3 main.py 逐行输出 baseline=1.00 和 candidate=0.50。仅验证指标实现，不外推检索器优劣。只用标准库，讨论每阶段最多三句话。

这场讨论在 Mac 上使用已登录的 Codex 和 Gemini 4 Neon。两方共调用 7 次，随后 Codex 执行 1 次。
下面按阶段保留双方发言。执行报告里的本机路径已换为相对链接。

## 独立提案 · codex

交付单文件 `main.py`：将前 3 条结果中属于固定相关集合 `{A, C}` 的论文数，除以相关论文总数 2，并用两位小数逐行输出。

验收：运行 `python3 main.py`，输出依次为 `baseline=1.00` 和 `candidate=0.50`。已知两份排名均无重复项；最大不确定性是材料未规定排名含重复论文时的计数规则，本次自检不受影响，也不据此判断检索器优劣。

CLI 报告 15,847 tokens。

## 独立提案 · gemini

基于已知的固定测试集与仅用标准库约束，交付单文件 `main.py`，核心函数 `recall_at_k(ranked, relevant, k=3)` 采用前 `k` 项去重后与相关集求交集再除以相关集大小的计算逻辑（假设：遵循标准集合去重口径），并以 `:.2f` 格式化逐行输出。验收标准为运行 `python3 main.py` 退出码为 0 且标准输出严格匹配预期的两行数值，同时可用截断位置与空匹配作为最小自检基线来证伪公式实现错误，且结论仅限指标校验而不外推检索器优劣。最大不确定性在于待验证的边界规范：若后续接入真实数据时出现重复文档 ID、排名长度不足 `k` 或相关集为空，应抛异常、返回 `0.00` 还是跳过，目前尚无已知约定。

CLI 报告 3,676 tokens。

## 交叉评议 · codex

值得采纳 Gemini 的前 3 项去重后求交集：它明确了相关论文按唯一 ID 计数的假设；Codex 的表述则未明确重复项如何计数，可能使召回率超过 1。两者对给定数据和验收结果无实质分歧；若要区分重复项口径，可用相关集 `{A,C}`、排名 `[A,A,B]` 检验：去重计数得 `0.50`，逐项计数得 `1.00`，但预期口径仍待约定。

CLI 报告 15,050 tokens。

## 交叉评议 · gemini

在已知无重复的固定输入下，两份提案输出完全一致、无实质分歧；codex 最值得采纳的是不预设未规定规则、紧扣题目保持最简。其最重要漏洞是假设输入恒定，直接按总数 2 计数而未做集合去重或空集防护，扩展输入时易出现召回率超 1.00 或除零问题。待验证的区分检验为：用 `ranked=[A,A,B]`、`relevant={A,C}`、`k=3` 测试，直接计数得 `1.00`，集合去重口径得 `0.50`。

CLI 报告 11,492 tokens。

## 候选方案 v1 · codex

采用集合交集计算：对排名前 3 项去重后，与相关集合 `{A, C}` 求交集，再除以相关集合大小；这能保证同一论文只计一次，也保持实现简洁。已知固定输入无重复，因此两种计数口径都得到相同结果；去重是本方案的假设，后续可用 `[A,A,B]` 检验：若约定结果应为 `1.00` 而非 `0.50`，则该假设被否定，相关集为空时的处理方式也仍待约定。

由实现者编写仅用标准库的单文件 `main.py`，由验收者运行 `python3 main.py`；验收条件是退出码为 0，标准输出依次且仅为 `baseline=1.00` 和 `candidate=0.50` 两行，结论仅限于这组指标实现自检。

CLI 报告 15,448 tokens。

## 表决 v1 · codex

赞成。方案满足固定输入、计算公式、输出格式和标准库约束；去重口径明确标为假设，不影响本次无重复输入的结果。重复论文和空相关集的规则仍待约定，无须阻碍本次自检。

CLI 报告 15,550 tokens。

## 表决 v1 · gemini

赞成。方案满足已知的单文件、仅用标准库、逐行输出两位小数及不外推检索器优劣等全部约束，且验收标准与退出码要求明确。它清晰区分了已知固定输入无重复的事实、前3项集合去重计数的假设，以及用[A,A,B]检验重复项口径和相关集为空处理规则等待验证项。无实质阻碍，可直接进入实现与验收。

CLI 报告 13,719 tokens。
